Today was less about shipping code and more about sharpening the mental model behind a couple of integration questions I've been sitting on.

### Mapping an accounting integration

I spent a chunk of the morning trying to understand where an external accounting tool actually fits in the workflow: reconciliation, automatic and manual write-offs, statement matching, accounts payable and receivable entries. The goal was to map the full flow end to end so I could tell the difference between what the API really exposes and what we'd only be mirroring for convenience. From that mapping I pulled together an agenda for an upcoming meeting: open questions, decisions still pending, and the pieces I need confirmed before writing any integration code.

### Straw-man, outbox, eventual consistency

The other half of the day was pure concept work. I dug into what a straw-man proposal is really for (a deliberately rough draft you expect to be torn apart), the outbox pattern for reliably publishing events from a transactional system, and eventual consistency in general.

One conclusion stuck: calling an external accounting API from inside the ERP's transaction is the wrong shape. Short-lived tokens, rate limits mid-order, and tight coupling all point to an async, outbox-driven flow instead. Slow day, but the abstractions got cleaner.
