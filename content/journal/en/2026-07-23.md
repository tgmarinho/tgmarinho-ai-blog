Today was less about shipping features and more about setting the stage: rules, guardrails, and pulling code closer to home so I stop depending on moving targets.

### Guardrails and conventions

Landed a batch of docs/CI work to enforce Portuguese domain names for business rules and table/entity names, since the domain itself is Brazilian. Only pure code stays in English. I also added a "interrogue antes de propor" discovery discipline for agents (§0.5) and general hygiene guidelines (§0.7), plus a CI rule to strip internal codenames from the repo and replace them with the official names. Adopted the guardrails/quality standards from a template repo and wired up Biome v2.5.5 across the stack.

### Skill curation

Installed and pruned skills across workspaces: three kunchenguid skills for diagnostics/validation/knowledge persistence, ten Matt Pocock skills for planning and workflow, plus targeted picks from Vercel labs, Anthropic frontend-design, shadcn/improve, and impeccable.style. Then went back and asked which ones actually made sense and which overlapped, cutting the noise.

### Vendoring tax calculators

On the tax simulator side, I ported the calculators (precision math plus ST/MVA/IPI/ICMS/DIFAL/PIS-COFINS/CBS-IBS) directly into the API instead of consuming them as a library. MIT license, so no attribution overhead. Owning the code locally means I can iterate without waiting on upstream updates, and it keeps the codebase self-contained.

Also spent time understanding MVA, IPI-ST, and TIPI conceptually before touching the math, and wrote it down in docs so the next session starts from context, not from scratch.
