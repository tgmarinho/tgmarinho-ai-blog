Today was a mix of shipping backend hardening and thinking hard about what data actually deserves to live in the database.

### Backend integrity pass

The big merge landed a set of changes for cross-tenant integrity, atomic numbering, and a batch of consistency checks. Concretely: making sure `empresa_id` and membership are enforced consistently across entities like activity assignments, and reasoning through what happens when many managers create activities concurrently for the same company. That pulled me into `ON CONFLICT DO UPDATE` semantics, row-level locking inside transactions, and where the real contention points are versus where I was imagining them.

### Less is more: passada as pure record

Closed out the "passada" rework by removing its persisted id entirely. It's static info for display, not something queried or joined on. Array order is enough, `useId` handles the frontend, and the database stops carrying weight it never needed. Wrote up the reasoning and closed the task without shipping extra code.

### Preview environments

Spent time mapping the current setup: Vercel frontend to Railway prod, PR previews on both sides, a fixed Railway staging without a matching frontend staging. The honest blocker is migrations, one preview's schema change can trip another.

### Learning mode

Read up on how large Postgres deployments trade features for scale, and what Aurora offers that vanilla Postgres doesn't.
